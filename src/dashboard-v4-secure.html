🔍 Why textContent Fixes the Vulnerability

Root Cause Analysis
JavaScript — The Fix Explaineddashboard-v4-secure.html
// ══ VULNERABLE (V1, V2, V3) ════════════════════════════════
const report = new URLSearchParams(window.location.search).get('report');
element.innerHTML = report;
// Input:  <img src=x onerror=stealToken()>
// Result: Browser PARSES this as HTML
//         → Creates an <img> element
//         → onerror event fires
//         → stealToken() executes
//         → Token stolen ✗

// ══ SECURE (V4) ════════════════════════════════════════════
const report = new URLSearchParams(window.location.search).get('report');
element.textContent = report;
// Input:  <img src=x onerror=stealToken()>
// Result: Browser treats this as PLAIN TEXT
//         → Displays the literal string on screen
//         → No HTML element created
//         → No event fires
//         → No JS executes
//         → Attack neutralized ✓

// ══ ALTERNATIVE: DOMPurify sanitizer ═══════════════════════
// If rich HTML rendering is required:
const clean = DOMPurify.sanitize(report, { ALLOWED_TAGS: ['b', 'i', 'u', 'p'] });
element.innerHTML = clean;
// DOMPurify removes all event handlers and dangerous elements
// while preserving safe formatting tags ✓
